# NOTE — your role:
#   Translate the natural-language query into concrete arguments for the maps.
#
# NOTE — object grounding:
#   The query may reference objects by placeholder names (object_1,
#   object_2, ...) or by their actual scene names. Pass each name through
#   verbatim into the map queries — e.g. get_avoidance_map('30cm from
#   object_1') — so the downstream map LMP can call parse_query_obj on
#   the real scene object.
#
# NOTE — value ranges:
#   distance: minimum 0, maximum 80 cm.
#   velocity: minimum 0, maximum 2 (1 = nominal speed). Express it as a
#   percent in the get_velocity_map query, where 100% = nominal.
#
# NOTE — you may choose freely:
#   You are free to pick ANY value in the allowed ranges. The cm and
#   percent values shown in the examples are illustrative anchors that
#   span the range so you can interpolate — do not feel bound to them.
#
# NOTE — keep the path feasible:
#   Pick values that still leave a feasible path to the goal. Too large
#   an avoidance halo can block every route — the robot will then fail
#   to reach the goal. When the scene is crowded, prefer the smaller end
#   of the range; when there is plenty of free space, you may use the
#   larger end.
#
# NOTE — only call maps you need:
#   Only call get_avoidance_map / get_velocity_map / get_rotation_map when
#   the scene actually requires that constraint. If there is no obstacle
#   to avoid, no slowdown to enforce, and no rotation target to face,
#   simply omit that map argument from execute_navigation rather than
#   emitting an empty or unnecessary one.
